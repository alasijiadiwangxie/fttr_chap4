# D4 经济驻留、滞回与 QoS 防振荡

**验收结论**　`ecq-sdps-d4` 已接入原有 B4 切换器。主信道干扰下，三种子平均完成切换从 D3 的 98.67 次降至 6 次，减少 **93.92%**。成功吞吐从 62.53 提升到 74.80 Mb/s，窗末未完成量从 131 降到 8 包。总能耗增加 10.33 mJ，每个成功交付比特的能耗下降约 16.0%。次信道干扰下的 VO/VI 准时率仍有下降，D4 在不同干扰下存在服务取舍。

## 1. D3 反复切换的证据

以 D3 已提交的主信道干扰场景为基线，从原始生成时刻、队列入队、重传回队、DATA 挑包和模式决策事件重建每次决策时的队列。报文在决策时已到截止时间且仍待发时，属于已经违约的报文。它仍占用真实队列和后续服务时间。

| --- | ---: | ---: |
| 完成切换 | 296 | 18 |
| 由紧急重判提交并真正开始的切换 | 232 | 6 |
| 两档均预测不可行仍真正开始的切换 | 276 | 0 |

种子 202 的 SFU 2 在 32.326850 ms 刚开始 LCM→HCM，同一时刻又收到一笔反向请求。此次紧急重判时有 26 个过期和 39 个未过期报文，两档均预测有时限风险。32.366975 ms 升档完成，同刻即开始降回 LCM。这条轨迹说明 D3 可以在上一笔切换仍在执行时就排入反向请求。全组结果同时显示，过期报文可能触发重判，但多数切换还有其他活跃业务参与，不能将全部振荡归于这些过期事件。

## 2. D4 如何决定换档

1. **先识别还能按时送达的报文。** D4 从原生成时刻计算剩余时限，已过期报文退出紧急触发和预计准时收益。它们仍按原队列规则发送，其发送、重传和等待继续计入后续服务和真实统计。未过期的报文沿用 C3 的整批服务估计加 B4 等待、实际切换时长、CCA 等待和 D3 安全裕量。
2. **两档都有风险时要求明确收益。** 按 VO、VI、BE、BK 比较第一类出现差异的业务。只有两档估计都有充分信息，且候选模式扣除 B4 时间成本后至少增加 0.5 个预期准时交付，才准许这种换档。预计已经错过时限的包，仅缩短其迟到时间不会带来准时收益。两档均可行时使用能耗门槛，一档可行时优先选择可行档。
3. **对反向切换增加保护。** 每台 AP 从真实 B4 完成时刻开始新驻留。经济换档采用配置的最小时间与预测回本时间两者中的较大值，QoS 换档采用配置的最小时间。保护期间继续收发并重判。若在下一周期或保护到期前等待就会错过一个已知报文的可挽救机会，可直接提交 B4。作为证据，保守预测须显示该包在当前模式达不到本 AC 的准时概率要求，候选模式满足要求。正在切换及实际完成的同一时刻禁止提交反向请求。保护到期表示允许检查下一次切换，原有周期或紧急事件仍决定何时重判。
4. **主动延迟也要值得。** 在 D3 时限上限、已有请求的到期时刻和观察终点之内，比较立即升档与先用 LCM 服务。只对能在等待窗内完成的本地整批报文记入预期成功量，扣除这一部分后，用相同 HCM 成本模型估算余下业务。未交付业务继续补计尾部服务成本。有完整批次可在 LCM 完成且同业务量成本确实更低时，才主动延迟。否则可立即提交，或在队列和信道变化后撤销。主动等待、B4 被动等待和实际切换分别记账。

### 空载回本怎么算

用 HCM 原地空闲作为同一时间基准。降档和未来再次升档的增量能耗分别为 `(8.75 − 7.62) W × 25.250 μs = 28.5325 μJ` 和 `(11.50 − 7.62) W × 40.125 μs = 155.685 μJ`。LCM 空闲每微秒省 `7.62 − 7.38 = 0.24 μJ`。首次空载降档、附加裕量为零时，回本需要 `ceil(184.2175 / 0.24 × 1000) = 767573 ns` 的 LCM 驻留。同长度比较还要留出两个切换时段，所以预测窗至少需要 832948 ns。Java 验证在 832947 ns 保持 HCM，在 832948 ns 允许经济降档。

有业务时，分母用 C3 在两档处理同一已知队列及 EWMA 预测到达量的稳态成本差，考虑退避、预期重传和可用信道时间。经济降档的成本包含等待、剩余业务和一次保守的再升档增量。D2 里的候选成本已经计入本次切换，D4 只追加潜在反向切换的增量预留。预留和预测回本时间用于决策，真实能耗仅记实际发生的活动。若预测稳态没有节能空间或可用时间覆盖不了回本时间，能耗理由不足以换档。

| 配置项 | 默认值和含义 |
| --- | --- |
| `wifi.ap.control.policy` | `off`。`ecq-sdps` 为 D3，`ecq-sdps-d4` 为 D4。单台 AP 可用 `sfu.N.wifi.ap.control.policy` 覆盖 |
| `wifi.ap.control.residency.minimum.us` | `500`。驻留最小值，设为 `0` 可取消基本时间门槛 |
| `wifi.ap.control.energy.margin.uj` | `0`。复用 D2 基础安全裕量 |
| `wifi.ap.control.residency.reverse.margin.uj` | `25`。发生过实际切换后，反向经济切换额外需要的净收益 |
| `wifi.ap.control.period.us` / `wifi.ap.prediction.window.us` | `5000` / `5000`。决策周期及预测窗 |
| `wifi.ap.control.qos.margin.us` / `wifi.ap.control.defer.max.us` | `50` / `2000`。保守时限裕量及主动延迟上限 |

## 3. 实验与结果

五种策略在每一组使用完全一致的业务和信道输入，按原始报文顺序比较指纹。主实验沿用 D3 的四组 120 ms 配置及种子 101、202、303。混合突发组为 2 SFU、各 2 STA、四类业务共 946 包。持续组为 1 SFU、1 STA、四 AC 泊松总负载 85 Mb/s。共同使用原 B3/B4 功率、HE SU MCS 7、GI 0.8 μs、A-MPDU 上限 8、BE AIFS 43 μs。主实验时限依次为 VO 650、VI 1400、BE 6000、BK 12000 μs，光侧使用 D3 的 0 μs 固定模型。实际配置由脚本生成。

无干扰场景关闭误包、干扰和扫描。干扰组沿用人工 SINR–PER 曲线和 C2 的 STA 反馈及 400 μs 辅助扫描。逻辑反馈延迟 100 μs，有效期 6 ms，空口时间配置为 0。D4 仅以已发生的扫描机会估计未来驻留 LCM 时的扫描平均附加功率，估计包含 HCM 当时跳过的机会。已经开始的扫描开销对候选共同存在。实际净能耗是 B3/B4 活动能耗加真实扫描的附加能耗，扫描只计一次。这些参数用于仿真验证，尚未经真实硬件校准。

主信道干扰组的 HCM 观察窗占比由 52.07% 升到 90.93%。D4 更常留在具备服务能力的模式，所以总能耗上升与成功交付增加同时发生。次信道干扰组总积压下降，但 VO 准时率从 97.22% 降到 91.11%，VI 从 99.33% 降到 96.89%。D4 该组的 HCM 占比从 14.68% 升到 71.85%，对应次信道影响更明显的模式。结果体现了当前保守判断在次信道场景的代价。无干扰突发中交付量相同，减少切换也没有降低总能耗。四种对照和 D4 的分 AC 结果均在性能 CSV 和图中。

P99 取已交付报文端到端时延的最近秩。准时率以已交付、显式丢弃及已到期未完成报文为分母。仍在途、未到期的窗口余量单独记录。吞吐只计窗内成功交付位数，净能耗和吞吐使用相同观察窗。性能和能耗图的柱高按种子平均，误差线给出最小与最大观测值。反向切换间隔图使用三个种子的合并样本。

169 项 Maven 定向与兼容测试全部通过，其中新增 13 项。75 次 Java 实验均通过逐事件对账。独立重放其中 35 次，两份 CSV 对应记录一致。与 D3 已提交结果相比，原四种策略在主场景的 660 条性能记录逐字段相同，另外 12038 条已选决策及模式事件的时序和动作一致。验证程序独立检查报文守恒、时长和能耗积分、最小驻留及紧急例外、过期触发资格、扫描历史、主动延迟收益和 B4 安全时序。

主要实现位于 `ApResidencyModePolicy`、`ApDeadlineModePolicy`、`ApEnergyModePolicy`、`SimulationContext` 和 `TraceLogger`。配置沿用 `ConfigLoader` / `ApModeController`，扫描开始和实际能力变化各增加一个只读记账入口。B4 的切换执行、PHY、EDCA、A-MPDU 和 PON/DBA 继续使用原有协议模型。

在线可见范围仍是本地队列、历史服务和已到达的信道观测。C3 用保守的整批时序估算截止风险，用近似同等服务组成折算主动延迟后的剩余业务，预测收益会随实际竞争、聚合和突发变化。两档观测不充分时更容易保持当前模式，可能错过及时降档机会。次信道实验和无干扰能耗结果保留了这些差异。
