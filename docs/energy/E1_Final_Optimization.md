# E1 FTTR 授权恢复与 ECQ-SDPS 预测优化

**E1a 修复了 E0 的光侧卡包，建议在后续联合仿真启用。E1b 减少了次信道和阶梯恢复场景中的无效切换，仍有预测偏高和部分业务准时率轻微下降的情况。** 两项功能可以独立启用，旧版本可直接重放。

| 功能 | E1 配置 | 冻结对照 |
| --- | --- | --- |
| PON 恢复 | `fiber.uplink.dba.mode=giant-complete-recovery` | `giant-complete` |
| AP 策略 | `wifi.ap.control.policy=ecq-sdps-e1` | `ecq-sdps-complete` |
| CCA 观测窗 | `wifi.ap.control.e1.cca.window.us=5000`，可改 `10000` 或 `20000` | D5 按上次周期重置 |
| E1b 消融 | `wifi.ap.control.e1.cca.enabled=false` 或 `wifi.ap.control.e1.urgent.guard.enabled=false` | 两项默认开启，仅作用于 E1 策略 |

## 1. E1a GIANT 授权恢复

### 恢复规则

收到**队首超限且实际发送 0 B** 的结算后，`PonDemandLedger` 为该 Alloc-ID 记下已证实失败的最大授权量。该值只说明目前的队首比它大。MFU 使用已到达的结算结果和 REPORT，未知队首的大小和身份。空队列造成的零实发不触发恢复。

`GiantDbaPolicy` 暂停该 Alloc-ID 的新增动态授权，等待已有预约结算。随后使用最新 REPORT、正常 SI/AB 阶段及帧剩余容量重算，试出的预算仍须超过已知失败值。不能装包的试算会重新分配帧内时间，其他队列可使用释放的容量。发生实际发送后清除旧失败值。固定预约照常占据时隙。已证实不足、且在任何可能移走队首的预约之前的固定时隙，仍执行原预约，账本不会将其预扣为将要发送的数据。已在途、可能发送的授权继续扣减。预算仍经统一校验和 BWmap 执行，SFU 按 FIFO 选择完整报文。

### E0 卡包重放

两条 1500 B、2.5 Gb/s、125 μs 帧、Type 3 两阶段额度各 2400 B。原 D5 和 E1a 共用相同到达时刻、REPORT 和传播参数。

| 目标帧 | 冻结版授权／实发（B） | E1a 授权／实发（B） | E1a 事件 |
| ---: | ---: | ---: | --- |
| 4 | 2400／1500 | 2400／1500 | 发送首包，返还 900 B |
| 5 | 600／0 | 600／0 | 首个不足额授权已提前发布 |
| 6 | 900／0 | 900／0 | 第二笔也在首个失败反馈到达前发布 |
| 7 | 600／0 | 0／0 | 等待 900 B 预约完成结算 |
| 8 | 900／0 | 1500／1500 | 发出完整授权，第二包在 1.015030 ms 到达 MFU |

| 孤立用例 | 冻结版交付 | E1a 交付 |
| --- | ---: | ---: |
| 单包 1200 B、额度 1200 B | 1／1 | 1／1 |
| 单包 1500 B、额度 1200 B | 0／1 | 1／1，保障与剩余额度同帧合并 |
| 单包 1500 B、额度 2400 B | 1／1 | 1／1 |
| 两包 1500 B、额度 2400 B、8 ms 轮询 | 1／2 | 2／2 |
| 同上，20 ms 轮询 | 1／2 | 2／2 |
| 两包 1500 B、额度 3000 B | 2／2 | 2／2 |
| 单包 1500 B、两阶段各 700 B | 0／1 | 0／1，明确记录 `RECOVERY_UNSERVICEABLE` |
| 两 Alloc-ID、850～1900 B、连续到达 | 11／12 | 12／12，逐队列保持 FIFO |

单阶段 1200 B 容不下 1500 B。若两阶段同帧都可用，合法合并额度仍能推进。两阶段相加只有 1400 B 的用例在确认容量上限后停止重复动态预约，报文留在队列。固定服务继续保留原服务周期。在为新拓扑设定容量时，也要留出控制和其他对象的预约时间。

## 2. E1b CCA 预测与紧急动作

### 可见信息与动作为何分开

`CcaHistory` 从固定长度的历史窗口读取实际侦听记录。周期和紧急决策都查询 `[t−窗口长度, t)`，查询本身不重置记录。B4 切换期间的侦听缺口保留为未知。LCM 平时只能看到主 20 MHz，已完成且未过期的辅助扫描能补充所扫子信道的时间片。HCM 某时段只要任一可见子信道忙碌即可确认宽带忙碌。判定宽带空闲需要各子信道同时可见且都空闲。重叠忙碌按时间并集只计一次。

当前物理 CCA、外部忙碌状态、历史占用、能判定的时间比例、各子信道最新样本年龄和连续忙碌时长分别记录。未判定的份额以 C3 的 25% 和 50% 先验生成期望与保守预测，同时保留未知份额全部空闲至全部忙碌的识别区间。每个子信道都有近期样本，才认为有足够近期证据比较档位。这里的「近期」取半个观测窗。非同时扫描能提供近期证据，不能把中间缺口算成宽带空闲。连续忙碌时长用于观察风险，不查询未来脉冲的结束时刻。

紧急队列事件仍触发完整重判。只有候选档按现有 QoS 风险比较有明确净改善、且能挽救一个等到下次周期就会失去机会的报文，才从该次紧急重判提交新切换。没有充分证据时记录 `REVIEW_ONLY`，保留已有合法请求。周期决策继续走 D5 的经济驻留、回本和主动延迟流程。定向 VO 用例在 0 μs 立即请求，满足 254.225 μs 的截止时间。

### 忙碌预测误差

先在 E0 原轨迹上同时计算旧值和新滑窗，关闭两项 E1 动作以保持原事件。种子 1201、SFU 2 在 35.984 ms 处，D5 用 0.984 ms 内的 0.750 ms 忙碌得到 **76.22%**。固定 5 ms 观测到 1.500 ms 忙碌，得到 **30.00%**。下一窗离线实测 **15.00%**。该点宽带时间覆盖 100%，绝对误差由 61.22 降至 15.00 个百分点。实测值只在日志后处理中计算。

下表使用独立种子 6719、9283 的相同决策轨迹，不混入动作改变后的样本。预测误差为预测减实测。覆盖指历史窗内已确定忙或闲的比例，D5 原日志没有可直接对比的时间覆盖。

| HCM 场景及取样 | 样本 | MAE 旧／5 ms 滑窗（百分点） | 偏差旧／新（百分点） | 滑窗平均覆盖 |
| --- | ---: | ---: | ---: | ---: |
| 次信道，全部重判 | 979 | 14.69／8.88 | −1.92／+4.85 | 60.27% |
| 次信道，整 5 ms 的周期点 | 156 | 11.99／11.62 | −1.28／+7.72 | 50.25% |
| 阶梯恢复，全部重判 | 2761 | 7.92／7.08 | +0.36／+4.40 | 75.57% |
| 阶梯恢复，整 5 ms 的周期点 | 398 | **5.78／13.09** | −0.55／+11.20 | 42.90% |

全部重判点的 MAE 降低，阶梯周期点未达标。低覆盖、干扰消退后的缺口仍按 25% 先验估计，给宽带预测带来正偏差。覆盖达到 80% 的子集，次信道 MAE 为 13.10→6.35、阶梯为 7.16→3.24 个百分点。LCM 周期误差原为 0，E1 约为 0.07／0.02 个百分点，来自切换期间的未知份额。种子 6719 的 10／20 ms 窗口周期 MAE 在次信道为 11.61／10.79、阶梯为 13.98／13.50 个百分点。5 ms 默认值在试验前按原决策周期确定，正式数据用于核对与记录局限。

次信道和阶梯完成切换分别降约 63% 和 70%。用种子 6719 逐次重放 69 次实际切换，对比同起点保持原档 5 ms。把优先顺序上首先出现的准时退化、准时持平而吞吐下降，以及两者持平但无能耗收益计为短窗无净收益。次信道 **15→2 次**，阶梯 **11→1 次**。两场景仍有准时率得失，次信道 E1 也比 D5 多耗约 0.73%。固定阈值在两组分别只切换 8、4 次，VO/VI 均比 E1 更准时。全部结果保留在 CSV。

只启用滑窗时，次信道／阶梯平均切换 23.5／10 次，阶梯的 VO／VI 准时率降到 84.61%／87.71%。只启用紧急动作保护为 27／27 次，阶梯切换仍高于 D5 的 23 次。组合后两种主要场景均有改善。持续高载保留一次升档，吞吐略增，VO 准时率仍略降。早期工程试跑曾把宽带低覆盖直接作为不可行动条件，8117、9539 的主信道与阶梯组全部留在 LCM，主信道吞吐从 64.276 降到 51.768 Mb/s。修正后将「每带近期有证据」与「知道多少并集占用」分开，正式验收改用预先固定的新种子。试跑轨迹和 JAR 保存在 `target/e1-optimization/pilot-results` 及其上级目录。

## 3. 核验和复现

- **光侧。** 6 个新增定向用例核对已知失败窗口、合法阶段合并、无合法额度、Type 5 固定预约、不同包长、多队列和跨帧连续到达。脚本从实际 REPORT、BWmap、装载、结算及交付事件复核队列和时间，对账实际字节加返还等于预约量，DATA 和控制时长加空闲量等于帧周期。
- **无线。** 7 个 CCA 历史用例及 5 个新增控制场景核查 5/10/20 ms、不可见时间、重叠、时效、保持原档和紧急挽救。B4、EDCA、A-MPDU、旧 DBA 和观测兼容用例合计 **179 项定向测试通过**，其中 18 项为本次新增。75 次 Java 场景运行和 69 次短窗保持重放核对了同输入、交付守恒、状态时间和能耗。9 个原 E0 控制回放与原记录一致。
- **边界。** 所有合法 E0 卡包用例均排空，700+700 B 用例明确报告不可装载。无线保留 B3 的研究功耗、人工 SINR–PER 曲线和辅助扫描抽象。次信道能耗、阶段周期误差和个别业务准时率退化仍是正式实测限制。

在仓库根目录运行。脚本将实际 `.properties` 和 Java 原始日志写入 `target/e1-final`，CSV 内含配置与逐包输入的校验值。绘图使用 Matplotlib 及微软雅黑，可用 `--font` 指定 Noto Sans CJK。
