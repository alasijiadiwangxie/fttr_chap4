# FTTR 仿真 C 阶段收尾验收

## 原模型的偏差定位

重放上一轮四种干扰、三个种子的高负载 HCM 配置，共 264 个完整的 5 ms AP 窗口。预测值来自窗口起点，实际值来自随后的 C1 窗口。吞吐包含 SFU 无线链路本地已经成功交付的上下行数据。上行输入是 AP 已接收的数据代理，STA 私有待发队列没有用于预测。

| 量 | 原预测均值 | 随后实际均值 |
| --- | ---: | ---: |
| AP 可观测新到达（Mb/s） | 118.76 | 116.39 |
| 无线成功吞吐（Mb/s） | 148.68 | 58.55 |
| 平均聚合深度（MPDU/PPDU） | 5.52 | 1.41 |
| AP TX（μs/窗） | 2405.75 | 1852.73 |
| AP RX（μs/窗） | 486.36 | 624.90 |

窗口平均输入偏差约 +2.37 Mb/s，同样的窗口里成功吞吐偏差约 +90.13 Mb/s。原模型用每 AC 总积压估算聚合深度，高估了连续发往同一 STA、同一 TID 的报文数量。它按 AIFS 和 CWmin 的一半估算接入，每个窗口内的实际多 AC、上下行竞争、碰撞后增窗和忙态冻结会改变可用于服务的时间。旧场景实际每窗平均发生 7.49 次下行 MPDU 重试。实际聚合以 C1 的 MPDU 总数除以 PPDU 总数计算，包含单包帧和 AP 已解码的上行帧。现有协议轨迹没有记录每个设备的完整 EDCA 计时器状态，空闲残差无法逐项归因到 AIFS、退避、NAV 或等待上行业务。

诊断选取 `high-*-hcm-*-timely-noscan.properties`。对每台 SFU，将 `WIFI_AP_PREDICTION` 的 `window_end_ns` 与下一条 C1 窗口边界配对，再汇总 AP 观测的到达、交付、分状态时长和聚合计数。这里选取的场景用于定位偏差，修正后效果使用独立种子验收。[上一轮验收配置](../../results/c-phase/configs)

## 模型与观测界限

启用修正模型使用 `wifi.ap.prediction.model=revised`。旧模型保留为兼容选项。预测在 C1 边界读取本机可观测的排队和发送历史，以及当时仍有效的信道报告。线上接口不接收离线分支后续报文或信道真值。

| 预测量 | 修正方法 |
| --- | --- |
| 理论 PHY 速率、有效 MAC 容量、成功吞吐 | 分别记录协商 PHY 速率、计入退避与重传的尝试字节容量、按当期预计需求和有限次重试成功概率计算的交付速率。MAC 容量是模型估计，短窗实测吞吐仍受实际需求约束。 |
| 聚合 | 下行读取 AP 队列中同一 AC/TID 内连续发往同一 STA 的报文，以实际 PPDU 时长和聚合字节上限截断。未来新到达只按已观测的目的 STA、方向和 AC 历史估计聚合深度。 |
| 接入与退避 | 使用有积压期间的可用时间、介质占用、外部忙时及 AP 的 AIFS、退避和冻结观测。满四个交换的历史窗可更新服务估计，期望接入时间用 75% 历史残差、25% 配置解析估计。该残差会包含本地可见竞争影响。 |
| 缺失信道信息 | 使用保守、期望和乐观的独立预算。候选忙时未知时，期望与保守下限分别是 25% 和 50%，两者保留已知主信道忙时这个下限。没有有效报告或可用历史的数据质量按先验和不确定性输出，并允许 QoS 暂不判定。 |
| 能耗 | 按 TX、RX、IDLE 及 B4 SWITCH 分段。增量服务能耗只积分 DATA 和响应帧对应 TX、RX 相对当前分段空闲功率的增量。实测同时保留含反馈 RX 的总增量，切换能耗单列。单位成功比特能耗以总能耗除以无线成功交付比特。零交付窗的相应比值为空。 |

## 离线验收口径

测试运行长 120 ms，使用 1709、2081、3191 三个独立于上一轮的种子。组合覆盖零负载、近零、低、中、高负载，1、2、4 台 STA，主信道、次信道和宽带干扰，以及及时、延迟、过期和丢失的反馈。两套在线预测器复用相同的业务输入和配置，验证预测开关前后的原协议轨迹一致。每个试验在 30 ms 和 70 ms 分别验证随后 5 ms。

候选切换通过独立 Java 进程重放。该分支与保持模式的试验逐包输入一致，预测时刻及以前的协议事件序列逐行一致，CSV 保存共同前缀的 SHA-256。B4 手动切换请求在预测后 1 ns 投递，实际开始等待原协议释放资源。比较窗口包含这个等待和实际切换，分支结果只在退出 Java 后用于验收。

候选模式的 QoS 验收以每个 AP、AC 和候选分支的一批下行报文为单位。该批次包含预测起点尚未终结、且在预测窗口结束前已生成的报文。每个报文依原生成时刻核对自己的截止时间，使用分支自然排空后的交付和丢弃记录。实测准时率达到配置阈值即为可行。没有报文的样本保留为 `NO_COHORT`。信息不足的非空批次单列并计入覆盖率分母。错误可行表示预测承诺可行而分支准时率不足，错误不可行表示预测拒绝了实际可行的分支。

吞吐偏差为预测减实测。MAE 和 WAPE 保留零吞吐窗，WAPE 的分母为组内实测吞吐之和。MAPE 仅对实测为正的窗口定义，同时报告有效样本数。CSV 的到达误差与服务残差采用离线归因，以真实到达替换预测到达，固定模型给出的服务约束及起点积压，再将剩余与实测的差记为服务残差。两项相加得到原有吞吐偏差，归因仅用于解释。

## 结果与复现

54 组配对场景共执行 216 次 Java 仿真，其中 108 次为独立切换分支。两种在线模型的逐包输入和原协议轨迹一致，所有分支均通过共同前缀、报文守恒、B2 无线时长和 B3 能量积分检查。代表性零负载及高负载场景另外核对了分支在预测时刻及之前的预测与观测轨迹。全量独立重放后，生成的配置和两份 CSV 逐字节一致。表中包含 432 条预测对照和 2592 条 QoS 记录。

### 成功吞吐与能耗

下表每行给出旧模型到修正模型的变化。偏差和 MAE 覆盖所有负载，每行每模型 54 个完整窗，包含 12 个零吞吐窗。中高负载 MAPE 单独使用其中的 36 个窗口。

| 被验证分支 | 偏差（Mb/s） | MAE（Mb/s） | WAPE | 中高负载 MAPE |
| --- | ---: | ---: | ---: | ---: |
| 保持 LCM | +8.18 → −0.43 | 10.15 → 3.80 | 45.29% → 16.96% | 47.24% → 15.71% |
| 保持 HCM | +52.48 → +0.92 | 53.14 → 6.05 | 159.20% → 18.11% | 161.59% → 18.62% |
| 切换到 LCM | +15.82 → +0.07 | 16.64 → 3.97 | 76.71% → 18.31% | 96.87% → 20.51% |
| 切换到 HCM | +95.97 → −7.36 | 96.23 → 8.43 | 247.45% → 21.67% | 277.24% → 19.69% |

保持模式的两组中高负载都达到 20% 工程目标，切到 LCM 的中高负载为 20.51%。切到 HCM 在中高负载平均低估 11.41 Mb/s，可能因此拒绝实际有服务能力的候选。零负载、近零和低负载合并后，保持 LCM/HCM 的修正 MAE 为 1.50/1.51 Mb/s，WAPE 为 46.99%/49.22%。这两组各 18 窗，其中 12 窗没有实际交付。216 个修正预测的保守、期望、乐观估计均按顺序排列，实测落在保守至乐观区间的比例为保持分支 73/108、切换分支 62/108。这些范围是模型情景估计，置信覆盖率尚未校准。

| 被验证分支 | 总能耗 MAE（μJ） | DATA/响应增量能耗 MAE（μJ） | TX/RX 时长 MAE（μs） | 单位成功比特能耗 MAE（μJ/bit） |
| --- | ---: | ---: | ---: | ---: |
| 保持 LCM | 1308 → 284 | 1312 → 288 | 875/372 → 235/293 | 0.173 → 0.138 |
| 保持 HCM | 1084 → 310 | 1090 → 310 | 396/120 → 88/111 | 0.180 → 0.124 |
| 切换到 LCM | 1070 → 261 | 1078 → 264 | 697/289 → 194/234 | 0.206 → 0.142 |
| 切换到 HCM | 1327 → 913 | 1318 → 933 | 469/140 → 290/180 | 0.191 → 0.125 |

实测 RX 时长含反馈，预测 RX 时长估计 DATA 和响应帧。B3 空闲能耗占比较大，因此总能耗误差小也可能伴随明显的 TX/RX 时长误差。切换到 HCM 时，RX 时长误差扩大，DATA/响应增量能耗整体偏低。单位成功比特能耗只对预测与实测成功比特都为正的窗口比较，零值配对仍在 CSV 中保留。

### QoS 判定

每种策略有 616 个非空样本及 248 个无待验收报文的样本。覆盖率为实际给出可行或不可行判定的样本占非空样本的比例，正确率以给出判定的样本为分母。

| 策略 | 错误可行 | 错误不可行 | 正确判定 | 信息不足（占非空样本） | 覆盖率 | 已判定正确率 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 原期望 | 21 | 138 | 279 | 178（28.90%） | 71.10% | 63.70% |
| 修正后期望 | 0 | 147 | 204 | 265（43.02%） | 56.98% | 58.12% |
| 修正后保守 | 0 | 167 | 184 | 265（43.02%） | 56.98% | 52.42% |

错误可行从原模型的 21/616 降至 0/616。按已判定样本计算也从 21/438 降至 0/351。保守配置相对修正后期望没有进一步减少错误可行，多了 20 个错误不可行。切到 HCM 的 155 个非空样本中，修正模型均因缺少完整宽带忙时观测而暂不判断，这部分也是错误可行减少的原因。进入 D 阶段可先用修正预测做受控接口与回退验证，实际切换策略仍需解决宽带观测覆盖和保守性权衡。

### 单窗口对账

独立种子 1709、无外部干扰、4 台 STA、高负载的 HCM 保持分支，在 30 ms 预测下一窗的可见输入为 110.72 Mb/s，实际为 112.80 Mb/s。成功吞吐从旧预测的 189.97 Mb/s 修正至 63.27 Mb/s，实际为 62.40 Mb/s。预测聚合深度从 5.42 降至 1.28，实际下行深度为 1.23。这个窗口的离线归因将原成功吞吐偏差约 +127.57 Mb/s 归于服务残差。起点已有严重积压，替换到达预测不会放开服务约束。

在预测前的 5 ms 内，AP 始终存在已知下行业务。介质占用约 3112.8 μs，AP 观测的 AIFS、退避、冻结分别约为 1125.2、702.0、3172.8 μs。冻结可能与介质占用重叠，后者不能再和接入阶段时长直接相加。同期记录 22 个下行 PPDU、2 个已观察的上行 PPDU，以及 31 次下行 MPDU 尝试和 28 次确认。旧模型把单个 BE PPDU 的接入时间估为 43 μs AIFS 加 67.5 μs 平均退避，多 AC 与上下行竞争通过窗口残差进入修正估计。

### 定向测试与运行

81 项 Maven 定向测试全部通过。解析单包用例的 HCM 预测在 1 ms 内交付 1500 B，需求限制后的成功吞吐为 12 Mb/s。含 AIFS 的服务时间为 164.6 μs，有效 MAC 容量约 72.90 Mb/s，TX/RX/IDLE 分别为 77.6/28/894.4 μs，增量服务能耗为 253.728 μJ。聚合 FIFO、缺失或过期 CSI 范围、切换能耗分列以及观察开关兼容也纳入定向测试。

mvn -o '-Dtest=ApServicePredictionTest,ApAnalysisTest,ApAnalysisSimulationTest,ApTrafficObservationSimulationTest,AmpduSimulationTest,ExternalCcaSimulationTest,ChannelManagementTest,ApModeSwitchSimulationTest' package
