# E3｜ECQ-SDPS 容量约束与经济决策修正

E3 修正了两类问题。50 Mb/s 恒定负载下，平均切换从 31.33 次降至 1.33 次，吞吐和准时率相同，完整结算能耗降低 1.23%。强主信道和次信道 15% 干扰下，吞吐提高、窗末积压减少。次信道 35% 下，E3 仍有明显积压，VO/VI 准时率均值小幅下降。相对 E1 的改善集中在有足够证据证明另一档能更好地服务的场景。

E3 通过 `wifi.ap.control.policy=ecq-sdps-e3` 启用。原 `ecq-sdps-e1` 仍可直接选择。冻结参考为 E2 提交 `fdb20aa`，E1 核心来自 `b20968f`。[E2 正式实验](E2_Thesis_Experiments.md) · [E1 冻结对照](../../results/e3-decision/baseline-check.csv)

## 1. 改代码前的诊断

使用 E2 种子 11317。将 E1 的原动作和替代动作从同一个时刻分叉。分叉前的报文、队列、CCA、扫描、MAC 和活动事件用同一 SHA-256 核对。替代分支在指定时刻请求 HCM，并在对照窗口内保持该档，实际请求仍走 B4。窗口内统计实际交付量、准时交付和 AP 能耗。分支结果用于诊断。

| 场景与分叉 | E1 实际分支 | 反事实保持或请求 HCM |
| --- | --- | --- |
| 50 Mb/s，45 ms 后 15 ms | 预测降档净省 37.96 μJ。实测切换 2 次，53.60 Mb/s，127.036 mJ | 切换 0 次，53.60 Mb/s，126.061 mJ |
| 主信道强 35%，55 ms 后 25 ms | 两档均为截止时间风险，保持 LCM。28.86 Mb/s，VO/VI 准时 18/7 包 | 47.17 Mb/s，VO/VI 准时 25/24 包 |
| 次信道强 15%，50 ms 后 25 ms | 两档均为截止时间风险，保持 LCM。41.79 Mb/s，VO/VI 准时 27/22 包 | 71.04 Mb/s，VO/VI 准时 29/26 包 |
| 次信道强 35%，50 ms 后 25 ms | 保持 LCM。41.79 Mb/s，VO/VI 准时 27/22 包 | 49.92 Mb/s，VO/VI 准时 22/22 包 |
| 原消融场景，50 ms 后 5 ms | 保持 LCM。42.24 Mb/s，VO/VI 准时 1/1 包 | 77.28 Mb/s，VO/VI 准时 1/1 包 |

50 Mb/s 的 E1 决策在 45 ms 预测 LCM 平均聚合 3 包，HCM 约 1 包。两档预计都能交付 257.7 kbit，净节能只高于当时 25 μJ 滞回门槛约 13 μJ。该决策时已观测到上一窗 64.8 Mb/s 的到达率，两档短窗的估计服务能力却分别只有约 54.9、53.0 Mb/s。继续留在 HCM 的等交付量分支实测少用约 0.975 mJ，说明这次经济收益受业务波动和聚合估计影响。

拥塞时，已违约报文仍要占用服务时间。原来的判断只有看到当前剩余报文的准时收益才通常允许换档，因此即使另一档能更快排空，也可能显示 `HOLD_UNPROVEN_QOS`。次信道 15% 和 35% 在这次 LCM 观测点给出了相同的 HCM 点预测，反事实的实际吞吐和 VO 收益却不同。原消融场景的短窗升档有服务收益，15 ms 时原分支也已升档，两条路径的结果随之接近。关闭信道感知或 QoS 能改变何时进入 HCM，也可能放过原来会触发保守留档的风险，因此在部分场景有收益。两档的实际 CCA 在消融时都照常执行。[逐决策与反事实数据](../../results/e3-decision/counterfactual.csv)

## 2. 修正内容

### 容量保护

- 分开记录四个量。到达率读取 C1 的新增业务计数，有效服务容量是持续有工作时的估计服务率，成功量是考察窗内预计实际交付的比特。积压观察本地待发、在途和队首等待。
- 每个 AP 只在完整周期确认持续缺口。队首已等至少一周期，且实际到达量高于成功交付量，连续两个同档周期才形成容量证据。紧急复核仍即时执行，混合模式窗口和不完整窗口不用于形成这条证据。C1 与决策周期不同时，已关闭的小窗和当前窗的累计差值组成同一个决策周期。
- 两档均有截止时间风险时，先保留可信的紧急救援。缺少明确的准时收益时，候选仍可因容量恢复而获选。它须有近期信道证据、可执行的切换时间、更高的持续服务能力，并预计减少未服务比特。窗内成功量至少超过“当前档预测与近两窗实际成功量的较大者”，门槛为典型一包和该参照的 10% 中较大值。容量动作也检查 VO、VI 的可挽救准时量。LCM 与 HCM 都可以成为容量恢复的目标。
- 若已观察到宽档连续忙碌可用完 VO/VI 的时间预算，而主档没有同等长度的忙碌段，则保持窄档的高优先级接入机会。真实可证的 VO/VI 紧急救援仍可执行。四次带新鲜分频段证据的无额外忙碌周期才撤销这一风险证据。未知或过期的观测不算恢复。

### 经济切换校验

- 两个选项的业务量与 5 ms 起点相同，各自结算等待、切换、服务和未交付业务的预计排空成本。比较完整结算能耗时，也给先完成的一方补到共同结束时刻的空闲能耗。当前切换在原成本中已经计费。未来可能反向切换的增量沿用 B4 预留，额外计入一次。
- 经济收益同时经过点预测，以及“原档乐观、候选档保守”的误差校验。两种排空口径均须跨过经济裕量。候选档的保守有效服务能力还须能承受近期业务波动。波动上沿取当前完整窗的实测到达率与“EWMA 预测加近期绝对预测误差”中的较大值。预测误差只用过去的预测和当前已结束的观测更新。
- 原 5 ms 周期、紧急 QoS 触发、主动延迟、经济驻留和帧交换后切换继续使用。上面的经济校验作用于纯经济动作，容量证据和紧急救援有各自的入口。

两个独立开关默认开启。关闭其中一个回退对应部分的 E1 规则。

| 配置 | 用途 |
| --- | --- |
| `wifi.ap.control.e3.capacity.enabled=false` | 关闭持续容量恢复及其高优先级接入保护 |
| `wifi.ap.control.e3.economics.enabled=false` | 关闭共同范围、误差和到达波动的额外经济校验 |

决策证据在 `ApDecisionRefinement`，选择顺序在 `ApResidencyModePolicy`。接入沿用已有 C1/C3、E1 CCA 与 B4。实验使用 E2 原 PHY、EDCA、A-MPDU、功耗、信道以及 `giant-complete-recovery` 配置。

## 3. 独立定向验收

开发种子为 61363、67211、71287。冻结 E3 规则后，验收用 74897、78781、82139、87223、91577、96401。E2 种子只作诊断和冻结轨迹核对。9 个代表场景按 E2 的 500/600/800 ms 窗口与同一流量配方运行，主对照为固定阈值、Always-HCM、E1、E3。验收共 348 次 Java 仿真，含独立消融。

下表为种子均值。完整能耗包含实际排空。差值先按同一种子计算再等权汇总，区间为双侧 95% 配对 t 区间。正能耗差表示 E3 多耗电。

| 场景 | 吞吐 E1 → E3（Mb/s） | 窗末未完成 E1 → E3（包） | 完整能耗差 E3 对 E1（95% CI） | E1 → E3 切换（次） |
| --- | ---: | ---: | ---: | ---: |
| 31 Mb/s | 31.05 → 31.05 | 0.8 → 0.8 | 约 0.00% | 1.67 → 1.00 |
| 50 Mb/s | 49.92 → 49.92 | 1.0 → 1.0 | −1.23% [−1.65%, −0.82%] | 31.33 → 1.33 |
| 85 Mb/s | 85.00 → 85.00 | 1.3 → 1.3 | 0 | 1.00 → 1.00 |
| 主信道强 35% | 35.01 → 47.33 | 1128.7 → 599.8 | −16.96% [−34.57%, +0.66%] | 0.83 → 2.00 |
| 次信道强 15% | 49.54 → 60.54 | 508.8 → 42.8 | −16.52% [−31.68%, −1.35%] | 2.83 → 6.00 |
| 次信道强 35% | 41.32 → 41.66 | 855.3 → 844.0 | −2.08% [−5.03%, +0.87%] | 1.33 → 2.00 |
| 周期突发 | 28.36 → 28.36 | 0 → 0 | +0.45% [+0.42%, +0.48%] | 20.00 → 19.00 |
| 阈值附近 | 31.16 → 31.16 | 1.5 → 1.3 | 约 0.00% [−0.02%, +0.03%] | 2.83 → 1.00 |
| 原消融场景 | 28.43 → 28.79 | 63.5 → 45.0 | −2.10% [−2.51%, −1.70%] | 10.17 → 12.67 |

50 Mb/s 的准时率均为 100%，P99 从 1.79 降到 0.80 ms。关闭经济校验后重新出现 E1 的 31.33 次切换。31 Mb/s 时 E3 相对固定阈值仍少用 0.66% 完整能耗，85 Mb/s 与 E1 一致。阈值附近相对固定阈值的 33.50 次切换，E3 平均仅 1 次。

验收种子 74897 的主信道强 35% 场景，E3 在 35 ms 观察到约 147.3 kB 本地积压。最近两窗实际服务为 28.88 Mb/s，而两档窗口预计成功量分别为 146.7 和 201.7 kbit。请求切换后先等完当前交换，35.252 ms 开始切换，35.292 ms 进入 HCM。窗末积压仍随流量增长，但增长速度下降。次信道强 35% 的同一种子在短暂升档后观察到更长的宽档忙碌，多次因 `KEEP_PRIORITY_ACCESS` 保持 LCM。该场景仍处于供不应求状态。

### VO/VI 与未达标项

| 场景 | VO 准时率差 E3−E1（百分点，95% CI） | VI 准时率差 E3−E1（百分点，95% CI） |
| --- | ---: | ---: |
| 主信道强 35% | +5.84 [+0.62, +11.06] | +15.01 [+4.11, +25.91] |
| 次信道强 15% | +3.72 [−0.33, +7.76] | +6.46 [+0.44, +12.48] |
| 次信道强 35% | −0.77 [−4.29, +2.76] | −0.57 [−2.50, +1.35] |
| 周期突发 | −0.23 [−1.26, +0.81] | −0.99 [−2.38, +0.41] |

- 次信道强 35% 只得到约 0.34 Mb/s 的小幅吞吐改善，完整能耗和两类准时率的区间均跨零。本组未证明 VO/VI 非劣，也未消除积压。全天候 HCM 在该组能提供更高总吞吐，但相较 E3 的 VO/VI 准时均值更低。观测不足时，容量与高优先级时限仍有取舍。
- 周期突发中，额外的经济校验使 HCM 驻留从 56.24% 提高到 81.04%，完整能耗增加 0.45%。相对固定阈值，全业务准时率仍提高 17.26 个百分点。相对 E1 的均值下降 2.14 个百分点，区间为 [−4.98, +0.71]。
- 固定阈值与固定 HCM 在部分强干扰场景仍更好。主信道强 35% 中，E3 相较固定阈值的完整能耗高 1.85%，全业务准时率低 2.57 个百分点。次信道强 15% 的固定阈值吞吐为 61.07 Mb/s、准时率为 84.15%，E3 为 60.54 Mb/s、70.30%。

### 消融

- 主信道强 35% 中只关闭容量保护，结果回到 E1 的 35.01 Mb/s、1128.7 包积压。50 Mb/s 中只关闭经济校验，重复经济切换和完整能耗同时回到 E1 的水平。
- 原消融场景中，只关闭信道感知使 HCM 驻留从 64.42% 增至 90.46%。关闭版本的准时率为 65.41%，完整策略为 51.92%。实际干扰相同，观测在本场景仍让策略较容易等待，容量修正只能消除其中一部分等待。次信道强 15% 也观察到相同方向的准时率差异。关闭 QoS 后，原消融场景完整策略的全业务准时率差为 −0.22 个百分点 [−8.09, +7.64]。次信道 15% 两版本的准时率均值为 70.30% 和 77.05%，因紧急复核次数与模式路径不同，单独差值以配对表为准。
- 原消融场景下 E3 正式运行没有执行主动延迟，关闭后指标一致。31 Mb/s 另有三次实际延期释放，分别等了约 0.162、1.497 和 1.532 ms。与关闭版本相比，吞吐和准时率相同，完整能耗差为 −0.001% [−0.014%, +0.012%]。这一组验证机制能执行，节能贡献尚未检出。

## 4. 对账、材料与复现

71 项 Maven 定向测试通过，包含容量双向选择、高优先级接入保护、到达波动、共同排空范围、独立消融开关、紧急救援、未来到达隔离和 1 ms C1 小窗合并。补充独立采样时钟后重放了全部 348 个验收配置，标准 5 ms 配置下的决策和性能逐项一致。冻结 E1 在 50 Mb/s、强次信道 35% 和周期突发的物理事件与重新构建后的 E1 逐字节一致。将 E3 两项修正均关闭后，这三个场景的物理事件在统一策略名后也逐字节一致。验收 348 次仿真共注入并交付 876,495 个报文，显式丢弃与最终未交付均为 0。逐次对账覆盖光侧时隙、B4 帧交换边界、各活动时长及窗内和排空能量。
