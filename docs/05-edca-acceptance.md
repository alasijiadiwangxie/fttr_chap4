# EDCA 基础模块综合验收

本次验收覆盖现有静态 HE SU、AIFS、CW、退避、CCA、单 NAV、设备内虚拟碰撞、跨设备碰撞、ACK 超时与重传，以及 TXOP。验收使用多 STA 上下行混合业务，按报文身份和每个 SFU 的占用区间检查结果，并对不同业务负载、随机种子和 TXOP 配置进行对照。

**统计口径**

现有 `summary=CLASS` 对应下行业务。现有 `wifi_queue_wait_us` 从进入无线队列算至最终成功的 DATA 开始，包含排队、接入冻结、失败 DATA 和 ACK 等待。性能验证工具根据逐事件轨迹重建每个发送设备、每个 AC 的 FIFO，提供上下行分别统计及双向合并结果。

| 指标 | 本报告的定义 |
| --- | --- |
| 排队时延 | 无线入队至成为本设备、本 AC 队首。前序报文在 ACK 成功或最终丢弃时退出队列 |
| 接入时延 | 成为队首至最终成功的 DATA 开始。包含 AIFS、退避、冻结、失败尝试及 ACK 超时；TXOP 续发包含帧间 SIFS |
| 总 MAC 等待 | 排队时延与接入时延之和，逐包与已有 `wifi_queue_wait_us` 交叉核对 |
| 端到端时延 | 源节点生成至最终目的节点收到 DATA。上行包含 SFU 至 MFU 的固定光侧时延 |
| 时延均值的样本 | 最终成功报文。失败报文由丢包率和失败计数单独体现 |
| 全程吞吐量 | 成功交付的有效载荷比特除以 0 至最后事件的仿真时长，包含输入结束后的排空阶段 |
| 输入窗口吞吐量 | 在流量生成窗口内交付的有效载荷比特除以该窗口时长 |
| 物理碰撞参与次数 | 该 AC 发起的碰撞尝试数。同一报文多次碰撞累计多次 |
| 虚拟碰撞次数 | 该 AC 在同设备同刻仲裁中失败的次数 |
| 重传次数 | 实际开始发送且 `retry_count > 0` 的尝试数 |
| 丢包率 | 最终重试超限丢弃数除以生成报文数。排空结束后校验生成量等于成功与丢弃之和 |
| TXOP 次数与持续时间 | 按持有者的 AC 归属计数，从首帧 DATA 开始至最后 ACK 完成 |
| AC 信道占用率 | 按 AC 分摊的占用时长除以 SFU 数与完整仿真时长之积。正常交换及 TXOP 间隔属于持有者；碰撞期间按同时发射的各尝试平均分摊 |
| 全局信道忙时 | 各 SFU 占用区间的并集，与原有 `wifi_busy_us` 比较。多 SFU 的占用时长之和可以大于该并集 |

占用包括被预约的 SIFS 和整个 TXOP。NAV 只约束接入时机，既不单独增加占用，也不重复累计碰撞中重叠的 DATA。

构建命令为 `mvn -o clean package`。当前验收执行 130 项测试，其中既有 126 项全部通过，新增 4 次综合验证全部通过。

**实验配置**

主实验采用 1 个 SFU、4 个 STA。SFU 与各 STA 独立发送，总输入的 50% 为下行，50% 为四台 STA 平分的上行。每个发送端的 VO、VI、BE、BK 分别建立等速率泊松流，报文均为 1200 B，便于比较接入参数的影响。PHY 使用 160 MHz、MCS 11、2 NSS、0.8 μs GI、默认封装与 PE；SIFS 为 16 μs，ACK 为 24 Mb/s，Slot Time 为 9 μs，光侧固定时延为 100 μs，最大重传次数为 3。

总到达率为 1000、5000、10000 packets/s，对应总输入 9.6、48、96 Mb/s。每次生成 1 s 的业务，随后继续执行事件，直至所有原始报文成功或最终丢弃。随机种子为 11、29、47、71、101。对照包括四类 TXOP Limit 均为 0，以及 VO 为 1504 μs、VI 为 3008 μs、BE/BK 为 0。另运行双 SFU 场景检查并行资源与统计口径。

这些是从空队列启动的有限输入实验。高负载结果应结合输入窗口吞吐量、排空时长、丢包率和队列时延阅读。各项均值与样本标准差按独立种子计算。

**模型边界与 Main 使用范围**

本模型适用于当前研究中的理想同信道、单 SU 数据帧交换和固定关联。空队列时尚未实现 post-backoff，新队首从完整 AIFS 和新退避开始。时隙边界采用现有离散事件抽象。Duration 使用精确时钟刻度，ACK Timeout 使用碰撞 DATA 结束后的可配置等待窗口。接收成功的 DATA 按既有规则交付，正常 ACK 确定成功。PHY 波形、ACK 丢失、隐藏节点及跨 SFU 干扰需按后续研究另行建模。

这些边界决定了当前测得的性能属于本仿真抽象。无线占用率表示资源预约时间，后续能耗研究仍须区分发送、接收、侦听和 SIFS 等状态的功率。

30 组主实验的各 AC 平均接入时延均符合 VO < VI < BE < BK。高优先级只影响竞争参数及设备内同刻仲裁，单包发送顺序仍由到达、退避和 CCA 决定。已有独立竞争测试验证了低优先级先发送的合法情况。

高负载时，VO 和 VI 能在生成窗口内交付大部分输入，BE 和 BK 出现明显排队及排空尾部。全程吞吐量包含排空时间，因而不能单独用来判断生成窗口内的公平性。TXOP 对这组负载下的 VI 时延和总吞吐量有改善，低负载下的个别指标也会随碰撞和随机序列波动。

**稳定性与统计交叉验证**

TXOP 全为 0 时，96 Mb/s 输入下的全程总吞吐量为 44.762 ± 0.195 Mb/s，跨种子的变异系数为 0.44%。

VO/VI 使用非零 TXOP 时，96 Mb/s 输入下的全程总吞吐量为 47.089 ± 0.123 Mb/s，跨种子的变异系数为 0.26%。

独立双 SFU 实验共生成 20,128 包，交付 20,031 包，最终丢弃 97 包。两信道占用时长合计 2,364,356 μs，全局占用并集 1,661,025 μs，表明存在独立并行。每个 SFU 内的占用区间均核对为互斥，数据与丢弃的字节总量也与输入一致。

31 组独立实验共检查 180,966 个原始报文、2,717,238 行日志。另一次固定种子运行与原运行的完整轨迹 SHA-256 相同。两个 TXOP 配置中相同负载、相同种子的生成报文序列也逐一相同。

统计重算器另用两包手算场景校验。1200 B 的两个 BE 报文在 0 μs 入队，DATA 分别在 79 和 320 μs 开始，ACK 在 187 和 428 μs 完成。平均排队为 93.5 μs、接入为 106 μs、总 MAC 等待为 199.5 μs、端到端为 263.5 μs，重算结果与手算完全一致。

本次识别并解决的验收缺口包括旧 CLASS 仅覆盖下行、队列等待和接入混在同一字段、碰撞参与次数与碰撞组数易混淆，以及多 SFU 占用相加与并集不同。通过独立轨迹重算及显式定义补齐这些统计，保留原有输出以便既有实验继续复现。受测路径中未发现需要修改协议状态机的错误。

**复现与交付**

在仓库根目录运行以下命令。Python 工具仅使用标准库，要求 Python 3.10 或更高版本。

```powershell
mvn -o clean package
python tools/validate_edca.py
```

[validate_edca.py](../tools/validate_edca.py) 自动生成配置、运行实验并逐行校验日志，默认输出 [runs.csv](../results/edca-acceptance/runs.csv)、[aggregate.csv](../results/edca-acceptance/aggregate.csv) 和 [verification.json](../results/edca-acceptance/verification.json)。verification.json 记录 JAR 与验证工具的 SHA-256、Java/Python 版本、配置、每组检查结果和重放哈希。原始日志在分析时流式处理，配置由工具中的 scenario() 确定性重建。

本次验收结论为通过，可在上述研究抽象内作为 Main 无线 MAC 基础版。默认配置及已有对照模式继续适用于回归，EDCA 和 TXOP 按显式配置启用。后续 PON/ECQ-SDPS 研究可以从这一基础版本签出分支。合入 Main 前由开发者审核当前工作区并提交版本。当前工作区也包含上一阶段尚未提交的 NAV 改动。
