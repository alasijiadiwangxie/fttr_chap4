# PON 上行帧调度测试报告

本阶段增加可选的 `fiber.uplink.mode=pon-framed`。多个 SFU 仍共用 2.5 Gb/s 上行资源。每台 SFU 保留独立的光侧 FIFO，MFU 在帧边界按全局 FCFS 确定本帧的发送时隙。专项场景以两台 SFU 发送 35 个 1200 B 报文，验证了单帧 32 包的容量边界、精确帧边界和多帧交付。

## 模型与统计口径

- `fiber.uplink.frame.period.us` 默认 125 μs，可配置为精确到整数纳秒的正周期。第 `i` 帧的逻辑发送区间为 `[i × periodNs, (i + 1) × periodNs)`。帧编号从 0 开始。
- SFU 在成功收齐无线 DATA 时入队。只有 `enqueueNs < frameStartNs` 的报文可获得当前帧授权。同刻入队以确定性的事件顺序仲裁。每确定一个授权，调度器再以原始入队时间比较各 SFU 当前的队首。
- 一条报文占一个完整时隙。串行化时长为 `ceil(packetBytes × 8000 ÷ rateMbps)` ns，起点为当前帧的剩余区间起点，终点为起点加串行化时长。队首装不下时，整条顺延且保持原顺序。配置预检拒绝单包超过整帧容量。
- 接收区间等于发送区间整体平移统一的上行传播时延，MFU 收齐时刻为 `txEndNs + propagationNs`。授权视为即时生效，发送时间仅按报文字节数计算。光侧发送、传播以及无线 ACK 可以独立推进。
- `PON_UPLINK_GRANT` 逐包记录帧号、SFU、入队、授权及发送窗口。`FIBER_TX_START`、`FIBER_TX_END` 和 MFU 的 `DELIVERED` 用于核对实际时序。授权等待为 `grantNs − enqueueNs`，按获得授权的报文取均值。原有 `PON_UPLINK` 的光侧排队统计到实际发送开始，包含授权后等到本包时隙的时间。
- `PON_UPLINK_FRAME` 记录该帧的授权包数、忙时、空闲时间和利用率。每帧利用率为串行化时长之和除以帧周期。`PON_UPLINK_FRAMES` 的总窗口从 0 到最后一个有授权的帧末尾，期间的空帧与最后一帧的剩余容量都计入分母，传播与无线忙时不计入分子。没有上行授权时，帧数、窗口及利用率均为 0。调度事件按积压唤醒，跳过的空帧在日志中按编号补记，仿真时间仍由实际事件推进。

## 专项运行实测

35 个 1200 B 上行报文按编号交替来自两台 SFU 下的 STA。报文 1–33 在 0 ns 入队，报文 34、35 在 250000、260000 ns 入队。使用手动流量和零时延无线配置隔离光侧时序，上行传播时延为 10025 ns，速率为 2500 Mb/s。两个相同配置的完整事件轨迹一致，35 个报文各交付一次，共 42000 B。

## 发现与下一步

本轮验证未发现丢包、重复交付或时隙重叠。在默认参数下，32 个 1200 B 报文发完还剩 2120 ns，严格 FCFS 会保留这段空闲时间。恰好在帧边界到达的报文至少等待一个周期，这是本模型的授权资格约定。

本阶段仍使用理想化 FCFS 和统一传播。GIANT DBA、BWmap、T-CONT、带宽请求与报告、保护间隔、突发前导和跨帧分片均留待后续。下一步可先为每台 SFU 建立帧边界队列快照和报告事件，再引入使用该快照的授权策略，以已有的即时共享和本阶段的分帧 FCFS 为对照。

## 复现

从仓库根目录运行。第一个命令构建 JAR 并执行完整回归。第二个命令单独运行 9 项帧调度测试。最后一个命令用 Python 标准库调用 JAR 两次，核对实际日志并重新生成 3 份复核文件。

```powershell
mvn -o clean package
mvn -o "-Dtest=PonUplinkFramedTest" test
python -B tools/run_pon_frame_test.py
```
